# v0.7 release contract: useful on somebody else's application

Status: Approved on 2026-08-27.

Linear project: Canvas Scan — Canvas Performance Investigator.

## Goal

A developer points canvas-scan at an application they did not write, built the
way applications are shipped, and gets a finding that names a place in their own
source.

v0.5 proved the ritual on controlled fixtures. v0.6 shipped to npm without a
release contract. v0.7 is the first release shaped by evidence from applications
nobody here controls.

## Why this release exists

Two dogfood runs against real applications, on 2026-08-21 and 2026-08-27, found
that canvas-scan was honest and not useful. The runs are written up in
`research/2026-08-21-polarsignals-dogfood.md`,
`research/2026-08-27-polarsignals-dogfood-rerun.md`, and
`research/2026-08-27-excalidraw-public-dogfood.md`.

Four defects and one boundary came out of them. All five are addressed here.

## Baseline

v0.6.2 provides bounded investigation sessions, four candidate finding types,
Canvas2D method evidence, interaction associations, explanation capture,
session comparison, and versioned JSON artifacts.

`InvestigationSessionV1` stays version 1. This release adds fields to it and
adds one value to an existing enumeration. It removes nothing.

## What changes

### C-1: A canvas is never forgotten

The lifetime cap evicted the oldest canvas and every window, reset and lifecycle
event recorded for it. On an application that keeps a cache canvas per element,
that is most of the recording: Excalidraw made 228 canvases in 18 seconds, and
44% of the evidence was discarded.

Eviction now folds a canvas's windows into the totals a finding is derived from
and drops only the per-window detail. The summary carries `windowDetailDropped`.
`compareSessions` refuses such a session, because a comparison needs the frames.

### C-2: An empty finding does not lead the list

`repeated-draw-work` had no floor, so a fast application produced a wall of
findings with no measured time. Excalidraw produced twelve, four of them 0 ms.

Those findings are still made and still keep their rank. They collapse behind a
count instead of filling the list a reader scrolls.

### C-3: A minified symbol is not a name

A production build renames every component. The four Excalidraw canvases that
resolved an owner gave `mRe`, `fRe` and `ERe`, and a finding headed
`Repeated drawing · mRe` looked exactly like one that had worked.

A display name that is a bundler's symbol now resolves as `minified-owner`. The
symbol is kept as evidence and never heads a finding.

### C-4: A canvas React never made has a place in the source

124 of the 128 Excalidraw canvases carried no React fiber, so the tool had
nothing to say about where they came from.

canvas-scan now takes one bounded stack where it first sees a canvas and keeps
the application frame as that canvas's creation site. Where the application
publishes a source map, the overlay resolves that site to the file and line the
developer wrote.

### C-5: The comparison states its own boundary

The comparison cannot answer for an application that resizes cache canvases and
composites them. Excalidraw returned 224 unknown windows out of 342. Every one
of those answers was correct, and nothing said so before a reader spent thirty
seconds recording.

The README names the application designs the comparison can and cannot answer
for. The overlay says so on the coverage line once half the frames or more come
back unknown.

## What this release does not claim

- It does not recover the comparison coverage lost on cache-canvas applications.
  It declares the boundary. Comparing across a reset that did not change the
  size is still open.
- It does not prove that canvas-scan reduces the time to a correct next check.
  `docs/north-star-benchmark.md` freezes the protocol that would. Nobody has run
  it.
- It does not resolve a minified owner's real name. It refuses to present the
  symbol as one, and gives the reader a source location instead.

## Compatibility

| Change | Effect on a v0.6 consumer |
| --- | --- |
| `windowDetailDropped` added to every canvas summary | Additive. A reader that ignores it sees v0.6 behaviour. |
| `minified-owner` added to `AttributionKind` | A consumer that switches exhaustively on the kind must handle it. |
| `compareSessions` refuses a truncated session | A comparison that used to run on an evicted recording now returns a refusal. |
| `sourceLocation` populated for canvases React never made | Additive. It was always `null` before. |

## Network behaviour

canvas-scan still sends no investigation data anywhere. It still fetches only
same-origin source maps, bounded in count and size, and only after something the
reader did.

This release adds one moment at which that happens: a recording that produced
findings asks for a source map, so a card can name the reader's own file. An
explanation still asks for one. canvas-scan never fetches on its own.
`pnpm --filter dogfood run network-silence:test` proves it with external access
cut off.

## Out of scope

OffscreenCanvas worker support, WebGL, framework-neutral owner names beyond
refusing a minified one, and any recovered comparison coverage.
