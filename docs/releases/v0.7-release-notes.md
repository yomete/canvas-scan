# canvas-scan v0.7.0 release notes

This release makes canvas-scan useful on an application you did not write and
did not build yourself. Everything in it came from pointing the tool at real
applications and writing down what went wrong.

## The headline

A finding now names a place in your own source, on a production build.

Before, a canvas created imperatively carried no owner and no location, and a
canvas whose owner did resolve on a minified build was labelled with the
bundler's symbol. On one real application that meant 124 of 128 canvases said
nothing, and the four that spoke said `mRe`.

## What changed

**Your source, not your bundle.** canvas-scan takes one bounded stack where it
first sees a canvas and keeps it as that canvas's creation site. Where your
application publishes a source map, the overlay resolves it to the file and line
you wrote. A canvas React never touched is covered by this, because it does not
go through React at all.

**A minified symbol is shown as one.** A display name that is a bundler's
counter resolves as `minified-owner` and is shown as `Minified owner · mRe`. The
symbol is kept, because you can search a bundle for it. It never heads a
finding.

**No canvas is forgotten.** The lifetime cap used to evict a canvas and every
window recorded for it — 44% of one 18-second recording. Eviction now keeps the
canvas's totals and drops only its per-window detail, and the summary says so
with `windowDetailDropped`. A comparison refuses a recording in that state,
because a comparison needs the frames.

**An empty finding does not lead the list.** Findings with no measured Canvas2D
time are still made and still keep their rank. They collapse behind a count
instead of filling the list you scroll to be sure you have seen everything.

**The comparison says what it cannot answer.** It compares a frame's commands
with the previous frame's, so an application that resizes cache canvases and
composites them leaves it nothing to compare. The README names which designs it
can and cannot answer for, and the overlay says so on the coverage line once half
the frames or more come back unknown. Every measured figure is unaffected, and
three of the four finding types never used the comparison.

## Also in this release

- One guided investigation against a URL you do not control, with an isolated
  browser profile: `node packages/dogfood/investigate-url.mjs --url=…`.
- A versioned agent handoff, JSON and JSONL, so a coding agent can read one
  investigation without parsing overlay text.
- A checked proof that canvas-scan sends nothing anywhere, run with external
  network access cut off.
- A pinned corpus of three real Canvas applications, and an advisory baseline
  that compares structure only and can never report faster or slower.
- A frozen north-star benchmark protocol. It has not been run.

## Upgrading from 0.6.x

| Change | What to do |
| --- | --- |
| `windowDetailDropped` on every canvas summary | Nothing. It is additive. |
| `minified-owner` in `AttributionKind` | Handle it if you switch exhaustively on the kind. |
| `compareSessions` refuses a truncated recording | Record again without hitting the canvas limit. |
| `sourceLocation` now set for canvases React never made | Nothing. It was always `null` before. |

## What this release still does not do

It does not prove that canvas-scan gets you to a correct next check faster. The
protocol that would is frozen in `docs/north-star-benchmark.md` and has never
been run.

It does not recover the comparison coverage lost on cache-canvas applications.
It tells you the coverage was lost.

It does not tell you a minified component's real name. It refuses to pretend the
symbol is one, and gives you a source location instead.
