## V04-02 — Record, stop, and export one investigation session

Type: AFK

Parent epic: Investigation sessions

User stories: US-1 and US-6

### North-star contribution

This issue lets a developer preserve the Canvas2D evidence from one slow
scenario instead of reading a moving live summary.

### What to build

Add the first complete recording path from public API and overlay controls to
a bounded, versioned JSON session. Use the existing canvas window reports as
the initial evidence. Keep passive Scan behavior unchanged outside recording.

The public module and IIFE global expose these operations:

- `startRecording()`
- `stopRecording()`
- `getLastSession()`

The exported artifact uses `schemaVersion: 1`. It includes session metadata,
canvas summaries, active windows, collection limits, dropped-entry counts, and
current command evidence. Later slices add method, episode, geometry,
lifecycle, interaction, and finding sections without changing the state
machine.

### Acceptance criteria

- [ ] Record and Stop controls use the same state machine as the public API.
- [ ] `startRecording()` starts from idle and is idempotent while recording.
- [ ] `stopRecording()` returns a deep-copied session when recording.
- [ ] `stopRecording()` returns no session while idle and changes no state.
- [ ] `getLastSession()` returns a deep copy or no session.
- [ ] A recording stops automatically at 30 seconds with `max-duration`.
- [ ] A manual stop records `manual`.
- [ ] One session keeps at most 10,000 active canvas-window reports and 128
  canvas lifetimes.
- [ ] The oldest complete report leaves first when a limit is reached.
- [ ] The artifact reports dropped counts and remains valid after eviction.
- [ ] The artifact contains no live object references, canvas arguments,
  pixels, input values, application text, or DOM snapshots.
- [ ] Existing `getReports()` and history behavior remain compatible.
- [ ] Starting and stopping a recording does not change command classification.
- [ ] The overlay survives application hydration and can start a second
  recording after the first completes.

### Required checks

- `pnpm --filter canvas-scan run test`
- `pnpm -r run typecheck`
- `pnpm --filter canvas-scan run build`
- `pnpm --filter demo run build`
- A real-Chrome probe that records, stops, exports, reaches the duration cap,
  and starts a second session.
- `git diff --check`

### Evidence artifact

A deterministic session JSON fixture, the real-Chrome probe result, and the
exact test output attached to the issue.

### Blocked by

- V04-01

### Intervention conditions

Stop only if the approved state machine or public method names need to change.

## V04-03 — Find heavy work in a burst-driven draw episode

Type: AFK

Parent epic: Canvas findings

User stories: US-2 and US-5

### North-star contribution

This issue helps a developer find a one-time expensive canvas draw even when
the application remains idle before and after the interaction.

### What to build

Add per-method counts and Canvas2D API self-time to recorded windows. Group
nearby active windows into draw episodes. Add a measured canvas work summary
and a `heavy-canvas-work` candidate. Show the result end to end in a
burst-driven flamegraph known-truth case.

Use the episode boundary from the release contract. Assign the existing native
method duration to the method that produced it. Do not add another clock read
per Canvas2D call.

### Acceptance criteria

- [ ] Each recorded window contains method call counts and available self-time
  by method.
- [ ] Canvas and episode summaries equal the sum of their stored windows.
- [ ] An episode starts and stops under the two-idle-boundary rule.
- [ ] One inactive boundary does not split an episode.
- [ ] Recording stop closes an active episode without synthetic activity.
- [ ] A continuous recording produces one open-ended episode until stop.
- [ ] Every non-empty session ranks canvas work by total self-time, maximum
  window self-time, and raster operations.
- [ ] One episode with at least 8 ms Canvas2D API self-time produces a
  `heavy-canvas-work` candidate.
- [ ] The finding shows top methods, counts, self-time, the maximum window,
  evidence level, claim boundary, and a next check.
- [ ] The finding never labels API self-time as GPU or render time.
- [ ] A burst-driven bad case ranks the seeded flamegraph canvas first.
- [ ] The fixed case keeps the same data and interaction and removes the heavy
  threshold result.
- [ ] The fixed case is not required to produce a `same` result.
- [ ] Count-only sampling keeps its current clock-read behavior.

### Required checks

- `pnpm --filter canvas-scan run test`
- `pnpm -r run typecheck`
- `pnpm --filter canvas-scan run build`
- A real-Chrome bad/fixed burst case with deterministic interaction steps.
- `pnpm --filter dogfood run bench:chrome`
- `git diff --check`

### Evidence artifact

Bad and fixed session JSON, the known-truth comparison, browser output, and
before-and-after hot-path benchmark results.

### Blocked by

- V04-02

### Intervention conditions

Stop if the 8 ms candidate threshold or episode boundary must change. Do not
change either rule inside implementation work.

### What to build

Record exact reset events inside sessions and connect them to active canvas
work. Add a `resize-churn` candidate with dimensions, affected episodes, and
unknown reasons. Prove it with bad and fixed known-truth modes.

### Acceptance criteria

  `reset()` produce the correct observed reset event.
- [ ] Failed native calls do not produce a reset event.
- [ ] One normal setup resize does not produce a finding.

  `resize-churn` candidate.
- [ ] Resets outside active raster work remain evidence but do not count toward
  the finding threshold.
- [ ] The finding shows reset count, dimensions, episodes, command status, and
  unknown reasons.
- [ ] The bad case resets during repeated active draws and produces the finding.
- [ ] The fixed case sizes only when dimensions change and does not preserve
  the finding.
- [ ] Existing reset barriers and false-`same` protections remain unchanged.
- [ ] Real Chrome proves native reset behavior; test fakes do not serve as the
  only reset evidence.

## V04-07 — Bound canvas lifecycle records without losing cache canvases

Type: AFK

Parent epic: Investigation sessions

User stories: US-1 and US-6

### North-star contribution

This issue keeps long investigations trustworthy and lets developers inspect
canvas replacement evidence without losing detached cache canvases.

### What to build

Record first-observed, detached, retired, and reactivated lifecycle evidence.
Remove inactive records from the active frame-loop registry after a bounded
idle period. Reactivate a record before its next wrapped call. Preserve its
canvas identity and fail closed on the first comparison after reactivation.

Use 120 inactive frame-loop boundaries as the retirement period. DOM
connection alone must not decide retirement.

### Acceptance criteria

- [ ] First observation records whether the canvas is connected to the DOM.
- [ ] A connected canvas that later disconnects records one detached event.
- [ ] A detached cache canvas that keeps drawing remains active and measured.
- [ ] An inactive record leaves the active iteration registry after 120
  inactive boundaries.
- [ ] Retirement does not remove the session’s copied historical evidence.
- [ ] The next wrapped call reactivates the same record before capture.
- [ ] Reactivation preserves the canvas lifetime ID.
- [ ] The first comparison after reactivation cannot report `same` against a
  stale baseline.
- [ ] A retired tracked source still supplies its current content token when a
  visible canvas draws it.
- [ ] A reset or draw on a retired source reactivates it before dependents use
  the changed token.
- [ ] Repeated create, detach, retire, and reactivate cycles keep the active
  registry bounded.
- [ ] The session shows lifecycle events as measured evidence, not as proof of
  a performance defect.

### Required checks

- `pnpm --filter canvas-scan run test`
- `pnpm -r run typecheck`
- Deterministic lifecycle and tracked-source tests.
- A real-Chrome detached-cache retirement and reactivation case.
- A long browser soak that checks active-registry bounds.
- `pnpm --filter dogfood run bench:chrome`
- `git diff --check`

### Evidence artifact

The lifecycle session JSON, soak summary, registry counts, browser result, and
hot-path benchmark output.

### Blocked by

- V04-02

### Intervention conditions

Stop if a safe implementation cannot preserve detached source behavior, canvas
identity, or the false-`same` boundary.

## V04-08 — Associate interactions and long frames with draw episodes

Type: AFK

Parent epic: Investigation sessions

User stories: US-5

### North-star contribution

This issue helps a developer connect burst-driven canvas work to the user
interaction and slow browser frame that occurred at the same time.

### What to build

Collect bounded event timestamps, Event Timing entries, optional user marks,
and Long Animation Frame entries during a recording. Associate entries with a
draw episode only when their monotonic time ranges overlap. Show association
as evidence, never causal proof.

Add `mark(label)` to the module and IIFE global recording API. Limit and clean
the label before storage.

### Acceptance criteria

- [ ] The collector feature-detects Event Timing and Long Animation Frames.
- [ ] Unsupported entry types appear in session feature flags and do not throw.
- [ ] Document capture records bounded timestamps for approved pointer,
  keyboard, wheel, input, and change events without wrapping app handlers.
- [ ] Stored event identity contains no input value, text content, live target,
  or full DOM path.
- [ ] Event Timing entries keep duration and `interactionId` when available.
- [ ] `mark(label)` records one bounded user mark only during recording.
- [ ] One session keeps at most 2,000 event, mark, and long-frame entries and
  reports dropped counts.
- [ ] An entry associates only when its time range overlaps the episode.
- [ ] One entry can associate with each overlapping episode without mutation.
- [ ] A nearby entry outside the episode range remains unassociated.
- [ ] The finding view uses “associated with” or “overlapped.”
- [ ] The claim-discipline test rejects causal wording.
- [ ] The burst-driven lab case associates its scripted interaction with the
  expected episode.
- [ ] A supported slow case records Long Animation Frame duration, blocking
  duration, and bounded script attribution.

### Required checks

## v0.5 epics only

Do not create detailed v0.5 issues until v0.4 release evidence exists.

Each v0.5 explanation starts from a selected v0.4 finding. It collects bounded
evidence that can narrow the hypothesis without changing the global hot path.

### Selective command explanation

Record normalized Canvas2D commands only for a selected canvas and bounded
window. Show the first meaningful command difference without retaining raw
application objects.

### Draw callsite evidence

Capture one bounded stack for selected draw work and resolve the application
callsite through development source maps without placing stack capture on the
global hot path.

### Session comparison

Compare two saved sessions through stable canvas and interaction identities.
Show measured changes and uncertainty without claiming an improvement from one
unstable timing sample.

## Later epics only

- Framework-neutral attribution beyond React owner data.
- A worker shim for `OffscreenCanvas` and cross-realm evidence transport.
- Repeatable Playwright capture for consumer applications.
- CI budgets based on saved investigation scenarios.
- WebGL support or integration with an existing WebGL investigation tool.
- Evidence-led external dogfood and separately authorized upstream work.
