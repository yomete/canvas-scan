# canvas-scan v0.8.0 release notes

This release resolves the seven issues from the 0.7.4 usage review
([#1](https://github.com/yomete/canvas-scan/issues/1) to
[#7](https://github.com/yomete/canvas-scan/issues/7)). It is also the first
release published from GitHub Actions through npm trusted publishing, with a
provenance attestation.

## What changed

**The overlay can get out of the way.** New `hideOverlay()` and
`showOverlay()`, also on `window.__CANVAS_SCAN__`. After an API-driven
`stopRecording()` the results panel takes pointer events inside the shadow
root, so it could intercept a Playwright click, and a `pointer-events` rule on
the host never reached it. `hideOverlay()` takes the overlay out of the layout.
Recording, explanation and comparison keep working while it is hidden. (#2)

**A comparison that cannot pair findings still says something.**
`compareSessions` has a session-level fallback. When findings cannot be paired
(`finding-not-found`, `finding-type-mismatch`, `incomplete-evidence`), the
artifact still carries session-wide self-time, raster, window and reset totals,
with a caveat that names the reason. The status stays `incomparable`. (#1)

**Unobserved canvases are counted.** Every session records
`observationCoverage`: canvases drawn through WebGL, WebGPU, bitmaprenderer, a
worker transfer or a main-thread OffscreenCanvas, counted by reason, plus the
canvases whose context was never seen. The comparison carries an
`observationNote` and the overlay a coverage line, so an unobserved renderer is
never read as a cheap one. Older sessions without the block are still accepted.
(#4)

**Guided runs keep every recording.** `investigate-url.mjs` takes `--tag=NAME`.
The tag goes into every file name, and a run into an `--out` directory that
already holds the same report moves to `DIR-2` instead of replacing the
baseline. Untagged names are unchanged. (#6)

## Documentation

- Playwright injection of the IIFE as the setup for temporary investigations,
  without changing application code. (#5)
- Instrumentation overhead, and why latency needs a separate run without
  canvas-scan. (#3)
- Sample-size guidance for before-and-after comparisons: one session per build
  is one sample. (#7)

`docs/investigate-url.md`, `docs/api.md`, `docs/limits.md`, `docs/findings.md`,
`docs/investigation-details.md` and both READMEs.
