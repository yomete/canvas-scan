## V05-02 — Add the bounded explanation state and artifact

Type: AFK

Parent: SIDPROJ-37

User stories: US-1 and US-5

### Outcome

A selected finding can start and stop one bounded detailed recording without
changing the v0.4 recording contract.

### What to build

Add `startExplanation()`, `stopExplanation()`, and `getLastExplanation()` with
the exact state, return types, 10-second limit, deep-copy behavior, and shared
recording behavior in the release contract. Add `ExplanationArtifactV1` with
source and follow-up session references, limits, drop counts, and unknown
reasons. Do not capture commands or stacks in this slice.

### Acceptance criteria

- [ ] All three methods exist on the module and IIFE global.
- [ ] Only a finding from the last session with an available canvas can start.
- [ ] Start returns each specified result and is idempotent while active.
- [ ] Start during a normal recording returns `recording-active` and preserves
  that recording.
- [ ] Explanation and normal recording start and stop together.
- [ ] Stop while only a normal recording is active changes nothing.
- [ ] Automatic stop occurs at 10 seconds and records `max-duration`.
- [ ] Normal recording remains capped at 30 seconds outside explanation.
- [ ] Stop and last-artifact access return deep copies.
- [ ] The artifact contains all fixed limits and no live references.
- [ ] Existing recording API and `InvestigationSessionV1` remain compatible.

### Required checks

- Focused state and public API tests.
- `pnpm --filter canvas-scan run test`
- `pnpm -r run typecheck`
- A real-Chrome start, manual stop, automatic stop, unavailable-canvas, and
  second-start probe.
- `git diff --check`

### Evidence artifact

One deterministic explanation metadata JSON file, the Chrome probe output,
and exact test output.

### Non-goals

- Do not capture commands or stacks.
- Do not add the overlay explanation view.
- Do not add session comparison.

### Blocked by

- V05-01

### Intervention conditions

Stop if the public method names, result union, shared recording behavior, or
10-second limit must change.

## V05-03 — Capture normalized commands and find the first difference

Type: AFK

Parent: SIDPROJ-37

User stories: US-2 and US-5

### Outcome

One selected canvas produces bounded, private command evidence with a known
first difference, known equality, or honest unknown result.

### What to build

Capture command entries only for the selected live canvas. Use capture-scoped
opaque value tokens and all fixed limits in the release contract. Compare
consecutive complete active windows by ordinal. Export the first difference,
same result, or honest unknown result.

Add three irrelevant positive variants, the identical-stream nearest negative,
and the unsupported-value unknown case. Expected results live outside the
product runtime.

### Acceptance criteria

- [ ] No explanation means zero command-entry allocations.
- [ ] An explanation captures only the selected canvas.
- [ ] Tokens preserve equality inside one artifact and cannot link artifacts.
- [ ] The artifact contains no raw argument values or deterministic raw-value
  digests.
- [ ] The capture does not invoke app iterators, accessors, or callbacks.
- [ ] The first difference uses one specified reason code.
- [ ] A complete equal pair returns `same` with no difference.
- [ ] A gap or unsafe value returns `unknown`; it does not guess.
- [ ] Every fixed cap records drops and invalidates affected comparisons.
- [ ] All positive variants find the seeded first difference.
- [ ] The nearest negative and unknown case produce the expected result.
- [ ] Copy never says same pixels, wasted, avoidable, or caused by.

### Required checks

- Focused normalization, privacy, cap, and comparison tests.
- `pnpm --filter canvas-scan run test`
- `pnpm -r run typecheck`
- A real-Chrome known-truth probe for all variants and negatives.
- A structural no-selection allocation counter.
- `git diff --check`

### Evidence artifact

Raw explanation JSON for every fixture row, the expected-result matrix, the
privacy scan, and the structural allocation result.

### Non-goals

- Do not capture stacks or resolve source maps.
- Do not add session comparison.
- Do not add command capture to passive scan.

### Blocked by

- V05-02

### Intervention conditions

Stop if implementation needs raw values, global capture, another comparison
algorithm, or a higher fixed cap.

## V05-05 — Capture one bounded draw callsite and resolve safe source maps

Type: AFK

Parent: SIDPROJ-38

User stories: US-3 and US-5

### Outcome

Selected draw work has one useful bounded callsite or an exact unresolved
reason without global stack cost.

### What to build

Capture the first selected raster-operation stack and current-command stacks
for first differences, subject to the eight-stack and twenty-frame limits.
Strip URL queries and fragments. Resolve only safe same-origin development
source maps, with eight lookups and 2 MiB per response. Export generated and
mapped locations, mapping status, and unresolved reasons. Export no source
contents.

Add direct, nested, and bundled positive variants plus the no-map nearest
negative. Show the bounded stack, mapped or generated location, and unresolved
reason in the selected explanation card.

### Acceptance criteria

- [ ] No explanation means zero stack capture and zero map lookup.
- [ ] Stack samples have the specified command relationship.
- [ ] All stack, frame, lookup, and response limits are enforced and exported.
- [ ] Cross-origin maps are not fetched.
- [ ] Query strings, fragments, source content, and `sourcesContent` are absent
  from the artifact.
- [ ] All positive variants map to fixture-owned expected source locations.
- [ ] The no-map negative keeps the generated frame and reports unresolved.
- [ ] The overlay shows the generated location, mapped location, mapping
  status, and unresolved reason from the exported artifact.
- [ ] The result describes a draw callsite and makes no causal claim.

### Required checks

- Focused parser, URL, limit, and source-map tests.
- `pnpm --filter canvas-scan run test`
- `pnpm -r run typecheck`
- A real-Chrome probe for all source variants and the negative.
- `git diff --check`

### Evidence artifact

Raw stack and mapping JSON, fixture-owned expected locations, request logs that
prove the origin and size policy, and exact browser revision.

### Non-goals

- Do not capture stacks outside an explanation.
- Do not fetch cross-origin maps or export source content.
- Do not claim that the callsite caused a finding.

### Blocked by

- V05-03

### Intervention conditions

Stop if useful mapping requires cross-origin access, source export, global
stack capture, or a higher fixed limit.

  delta claims.
- [ ] Session-local identity changes do not change expected structural deltas.
- [ ] The nearest negative returns `finding-type-mismatch`.

## V05-08a — Make every fixed explanation limit observable and fail closed

Type: AFK

Parent: v0.5 — Release confidence

### Outcome

Every fixed explanation limit has one public, machine-checkable result. A
command gap invalidates only affected command comparisons. A callsite limit
reports incomplete callsite coverage without changing a command result.

### Acceptance criteria

- [ ] Schema version 1 exports ten ordered limit results and ten matching
  rejected-count keys.
- [ ] Each result has the fixed maximum, exact count, reason, and first
  affected coordinate.
- [ ] Duration and selected-canvas limits use explanation coordinates.
- [ ] Command limits make affected comparisons unknown with the exact reason.
- [ ] Callsite limits keep command comparison truth unchanged.
- [ ] A 2 MiB map response passes. A 2 MiB-plus-one response reports
  `source-map-too-large` once.
- [ ] Same-selection explanation starts stay idempotent. A different valid
  selection records one rejection and does not replace the first selection.
- [ ] The overlay continues to hide different-type comparison actions.
- [ ] The mismatch negative uses public `compareSessions()` and has no
  measures.
- [ ] Real Chrome covers three irrelevant variants and one nearest negative
  for all ten limits.
- [ ] The checker rejects false counts, wrong reasons or coordinates, known
  command results across gaps, privacy leaks, forged map evidence, diagnostics,
  missing rows, and manifest changes.

### Required checks

- Focused core and checker mutation tests.
- `pnpm --filter canvas-scan run test`
- `pnpm --filter dogfood run lab:v0.4`
- `pnpm --filter dogfood run probe:fixed-limits`
- `pnpm --filter dogfood run probe:fixed-limits:check`
- `pnpm -r run typecheck`
- Core and demo builds.
- `git diff --check`

### Non-goals

- Do not raise a fixed limit.
- Do not capture global commands, stacks, raw values, pixels, map bodies, or
  source contents.
- Do not add external application dogfood or performance gates.

### Intervention conditions

Stop if the work needs raw application data, global capture, a weaker passive
gate, a higher limit, or schema version 2.

hashes, smoke-test artifact, release URL, and final Linear comment.

### Non-goals

- Do not weaken a failed gate.

### Blocked by
